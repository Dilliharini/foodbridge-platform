Build a production-quality full-stack web application called "FoodBridge".

IMPORTANT:
This is a portfolio-grade software engineering project, not a simple demo or static website.

The application solves a real-world problem: restaurants, hotels, event organizers, cafeterias and individuals often have safe surplus food that goes to waste because they cannot efficiently connect with NGOs and volunteers who can collect and redistribute it.

FoodBridge connects:

Food Donors → NGOs/Organizations → Volunteers → Food Recipients

==================================================
DONATION STATUS
==================================================

Implement a proper donation lifecycle.

Possible states:

AVAILABLE
REQUESTED
ACCEPTED
PICKUP_ASSIGNED
PICKED_UP
DELIVERED
COMPLETED
EXPIRED
CANCELLED

The backend must enforce valid state transitions.

Do not allow arbitrary status changes from the frontend.

==================================================
DONATION REQUEST WORKFLOW
==================================================

1. Donor creates donation.
2. Donation becomes AVAILABLE.
3. NGO searches/browses available donations.
4. NGO submits request.
5. Donor accepts or rejects request.
6. If accepted, a volunteer can be assigned.
7. Volunteer performs pickup.
8. Volunteer confirms pickup.
9. Volunteer delivers food.
10. Delivery is confirmed.
11. Donation becomes COMPLETED.

Prevent multiple NGOs from successfully claiming the same donation.

Use proper database constraints and backend transaction logic to prevent race conditions or duplicate acceptance.

Use JWT authentication.

Implement backend role-based authorization.

Do not rely only on frontend role checks.

Example:

DONOR can create donations.

NGO cannot create donations.

NGO can request donations.

VOLUNTEER cannot approve NGO requests.

ADMIN can manage platform resources.

Users must not be able to access another user's private resources simply by changing an ID in the URL.
